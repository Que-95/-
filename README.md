# Расписание группы: сайт на GitHub Pages + агент ВК

Сайт хранит **все недели** (архив), помечает прошедшие пары, умеет переключать бригады,
показывает сообщения куратора и имеет защищённую паролем админку, в которой расписание
можно править прямо на сайте. Данные лежат в этом же репозитории, отдельный сервер не нужен.

```
docs/index.html            сайт
docs/config.json           настройки: группа, хеш пароля админа (при желании — repo)
docs/data/index.json       список недель (архив)
docs/data/weeks/*.json     по файлу на неделю (имя = дата понедельника)
docs/data/messages.json    сообщения куратора
agent/                     агент ВК (скачивает PDF, разбирает, пишет в docs/data)
.github/workflows/         запуск агента каждые 20 минут
```

## Что умеет

- **Архив.** Каждый новый PDF — новая неделя в `docs/data/weeks/`. Старые недели не удаляются.
  На сайте над днями есть стрелки ‹ › и список всех недель (текущая, предстоящие, архив).
  Первый запуск агента сам добирает в архив все PDF, которые уже лежат в документах сообщества.
- **Прошедшие пары.** Пара, которая закончилась, затемняется и подписывается «прошла»,
  идущая подсвечивается, у дня показывается «осталось пар». Прошедшие дни в табах приглушены.
- **Бригады.** Кнопка «⇄ Бригада N» рядом с кнопкой темы.
- **Админка.** Маленькая кнопка в углу → окно с паролем (32 символа) → панель: правка пар
  (изменить, добавить, удалить), сообщения куратора, смена пароля. Правки сохраняются коммитом в репозиторий.
- **Агент не затирает ручные правки.** Неделя, сохранённая из админки, помечается `edited: true`,
  и агент её не перезаписывает (галочку «не затирать при обновлении из PDF» можно снять, и тогда
  следующий PDF обновит неделю).
- **Уведомления.** Оповещения о новой неделе и сообщениях; открытый сайт проверяет данные раз в 5 минут.

## Настройка

1. **Репозиторий.** Создайте репозиторий на GitHub и загрузите всё содержимое этой папки в ветку `main`.
2. **Сайт.** Settings → Pages → *Deploy from a branch* → ветка `main`, папка `/docs`.
   Адрес будет `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.
3. **ВК: документы.** Управление сообществом → Разделы → включить «Документы», загрузить PDF с «Расписание» в названии.
4. **ВК: ключ.** Управление → Работа с API → Ключи доступа → создать ключ с правом на документы.
   При ошибке 15 или 27 используйте ключ пользователя с правом `docs`. Узнайте числовой ID сообщества.
5. **GitHub Actions.** Settings → Secrets and variables → Actions:
   *Secrets:* `VK_TOKEN`. *Variables:* `VK_GROUP_ID`; по желанию `GROUP_NAME` (по умолчанию `65е`),
   `DOC_PATTERN` (часть названия файла), `WALL_TAG` (хештег записей куратора, например `#куратор`).
   Затем Settings → Actions → General → Workflow permissions → *Read and write permissions*.
6. **Первый запуск.** Вкладка Actions → «Обновление расписания из ВК» → *Run workflow*.
   В журнале будет видно, какие файлы найдены и какие недели добавлены.

## Токен для админки

Админка сохраняет правки через GitHub API, поэтому ей нужен токен:

1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token.
2. *Repository access:* Only select repositories → ваш репозиторий.
3. *Permissions → Repository permissions → Contents:* **Read and write**. Срок действия — по желанию.
4. На сайте: кнопка в углу → пароль → поле «Доступ к GitHub» → вставить токен.
   Токен хранится на этом устройстве в зашифрованном виде (ключ получается из вашего пароля), поэтому
   на каждом устройстве его нужно ввести один раз.

Репозиторий сайт определяет сам по адресу `логин.github.io/репозиторий`. Если у вас свой домен,
добавьте в `docs/config.json` поле `"repo": {"owner": "ЛОГИН", "name": "РЕПОЗИТОРИЙ", "branch": "main"}`.

## Пароль админа

В `docs/config.json` хранится только хеш пароля. Пароль, который вам выдали ранее, продолжает работать.
Сменить его можно в панели («Пароль администратора») — новый пароль тоже ровно 32 символа.
Пароль защищает интерфейс, а настоящую защиту записи обеспечивает токен: без токена, который есть только у вас,
сохранить что-либо в репозиторий невозможно.

## Важно знать

- GitHub Pages публикует изменения с задержкой примерно в минуту, иногда до нескольких.
  После сохранения у других людей правка появится не мгновенно.
- Если агент и админ одновременно меняют одну неделю, админка откажется сохранять и предложит
  отменить правки и повторить: чужие данные не затираются.
- Сообщения из ВК, которые админ «удалил» на сайте, не стираются, а скрываются, иначе агент вернул бы их при следующем запуске.
- Уведомления в закрытый сайт не приходят: для этого нужен серверный пуш (например бот Телеграма).

## Проверка и отладка

Агент пишет понятную причину сбоя в журнал запуска (Actions → последний запуск).
Частые случаи: раздел «Документы» выключен или у ключа нет права (ошибка 15), в названии файла нет слова
из `DOC_PATTERN`, группа в PDF названа иначе (в ошибке перечислены найденные группы).
Локально: `pip install -r agent/requirements.txt`, затем `VK_TOKEN=... VK_GROUP_ID=... python agent/vk_agent.py`.
